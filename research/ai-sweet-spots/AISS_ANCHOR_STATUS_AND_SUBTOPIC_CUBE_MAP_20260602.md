## 1. Bottom Line

AI Sweet Spots remains the anchor study family.

The new model does not replace the existing AISS operating model. It explains how to make AISS playable, measurable, reusable, and extensible through a cube-style interface and graph-backed research engine.

The canonical AISS program remains:

- research-first
- evidence-led
- subtopic-driven
- asset-backed
- productised only after evidence integrity is preserved

The new layer is:

```
AISS research graph
    ↓
Subtopic cube views
    ↓
Study dodecahedron states
    ↓
User / organisation / government simulator
```

## 2. Canonical Source Position

The existing operating model defines AI Sweet Spots as a 7-theme / 7-subtopic lattice, giving 49 canonical research cells. It states that research is the source of truth, subtopics consume research assets, and products/courses are packaged interpretations.

That remains the control point.

The simulator must reference the canonical AISS structure. It must not duplicate or overwrite it.

## 4. AISS Core Cube

The AISS root cube asks:

> What happens when this human meets this AI under these conditions, at this intensity, for this outcome?

Default faces:

1. Human profile
2. AI / technology profile
3. Context
4. Involvement / intensity
5. Signal
6. Outcome

Default face metrics:

- completeness
- confidence
- evidence strength
- risk
- drift
- actionability

- core discovery and evidence base

## 11. Decision

AISS is the first proof-of-system.

It should be used to build the first working cube because:

- it has canonical structure
- it has existing assets
- it has known product tiers
- it has known subtopics
- it has evidence and gaps visible
- it already asks the invariant human × AI × context question

The next build should not start with all 117 rows.

It should start with AISS Theme 1 — Sweet Spots Core — and seed the first 5 to 7 subtopic cubes.
