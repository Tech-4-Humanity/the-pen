# Clockworks Row Evaluation and Survivability Rules

## Purpose
Every existing research row, subtopic, idea, hypothesis, or future study must be able to enter the same evaluation engine without requiring architecture changes.

## Universal Rule
New rows must not break the model.

A new:
- study
- subtopic
- role
- machine
- signal
- place
- human factor

creates a new Clockwork and passes through the same engine.

## Evaluation Flow
Research Row
-> Universal Impact Matrix
-> Scoring Engine
-> GO/HOLD/WATCH/KILL
-> Clockworks Visualisation
-> Evidence Status
-> Next Action

## Scoring Outputs
- GO
- HOLD

## Visual Rule
The image is a diagnostic.
The image is not proof.

Default storyboard:
Current State
-> New Input
-> Variance
-> Diagnosis
-> Action
-> Improved Outcome

This storyboard was validated conceptually against all 117 research subtopics.

## Survivability Test
The model passes only if a new research topic can be added and immediately evaluated through:

Research Row
-> Impact Matrix
-> Score
-> Visual

without architecture redesign.

## Clockworks Principle
The engine evaluates rows.
The simulator evaluates interactions.
The highest-value discoveries emerge from Clockwork collisions.

Examples:
- AI Sweet Spots + Sleep Debt
- AI Sweet Spots + Consent-X
- AI Sweet Spots + Psychedelic Interaction Modelling
