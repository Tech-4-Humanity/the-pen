# Clockworks — Final Judge-Ready Synthesis

## 1. Starting Intent
The conversation began with AI Sweet Spots and the need to understand study themes, subtopics, human impacts, role impacts, machine impacts, signal impacts, places, and translation effects.

The need never changed: make every research topic and subtopic usable, comparable, scoreable, and visually explainable.

## 2. Final Concept
Clockworks is the canonical operating model.

A research topic is not merely a category. It is a mechanism.
A study is not just a record. It is a mechanism.
A subtopic is not only a row. It is a mechanism.

Each mechanism can affect people, organisations, machines, signals, places, policy, risk, strategy, and other mechanisms.

Therefore the research estate is not a static taxonomy. It is a network of interacting Clockworks.

## 3. The Correct Architecture
The architecture is:

Entities
-> Relationships
-> Clockworks
-> Clockwork Interactions
-> Universal Impact Matrix
-> Scoring Engine
-> Visual Diagnostic
-> Outcome / Next Action

The cube is not the architecture. The cube is a rendered snapshot.

## 4. Universal Row Rule
Every existing row and every future idea must be able to enter the same engine.

Input can be:
- research theme
- research subtopic
- study
- novel idea
- applied hypothesis
- new machine/system variable
- human factor
- signal
- place

The engine must return:
- impact matrix
- scores
- status
- evidence position
- visual diagnostic
- next action

If adding a new row breaks the system, the system is wrong.

## 6. Visual Diagnostic Rule
The image is not proof. The image is a diagnostic.

The universal visual sequence is:
Current State
-> New Input
-> Variance
-> Diagnosis
-> Action
-> Improved Outcome

This works better than Perfect Cube -> Broken Cube -> Fixed Cube because not all research topics are damage topics. Some are calibration, measurement, standards, ethics, or governance topics.
