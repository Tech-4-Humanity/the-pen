# Organisational Metabolism Runtime

## Purpose

This folder turns the service catalog change-governance concept into a factory-ready runtime workstream.

The public narrative is simple:

> Businesses have spent decades managing systems. The next phase is managing organisational metabolism.

The sellable customer entry point is not a giant platform pitch. It is a diagnostic offer:

> Give us your service catalog, request history, approval history, ownership data and evidence trails. We will show where your organisation is getting sick: stale services, blocked flow, orphaned ownership, approval hypertension, knowledge dementia, hidden dependencies and service debt.

## First wedge

Service Catalog Reality Audit.

Inputs:
- service catalog export
- request/ticket history
- approval history
- ownership data
- deprecated/retired service list
- KB metadata
- optional employee/customer signal data

Outputs:
- orphaned services
- stale services
- duplicate services
- approval bottlenecks
- service debt index
- evidence coverage score
- retirement candidates
- automation candidates
- top intervention backlog

## Runtime principle

Analytics alone is not enough. Every disease signal must produce an intervention object.

Signal -> diagnosis -> intervention -> owner -> expected benefit -> evidence -> outcome.
