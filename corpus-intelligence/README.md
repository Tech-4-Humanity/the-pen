# T4H Corpus Intelligence

Purpose: extract missed business value from LLM chats, browser sessions, docs, repos, and runtime evidence.

This is not a summary engine. It is a portfolio intelligence engine.

## Build rule

When Troy says build, finish, create, complete, launch, or deploy, interpret that as:

> deliver the outcome using the fastest, highest-reuse path available.

Execution order:

1. Reuse existing T4H asset.
2. Reuse existing internal component.
3. Search GitHub/open source.
4. Use or adapt commercial product.
5. Compose existing assets.
6. Build only the missing delta.

## No-HITL rule

Default mode: autonomous execution.

Human required only for:

- new credentials
- new secrets
- new external authority
- legal acceptance
- money movement
- irreversible external commitment

Everything else proceeds by inspect, repair, execute, verify, receipt, close.

## First outputs

- `CORPUS_AUDIT_V1`: weak signals, assets, markets, customers, revenue paths, abandoned ideas, orphan opportunities.
- `OPERATIONAL_DELTA_V1`: broken, degraded, newly released, up-and-coming, promotion-ready, rollback candidates, repair candidates.

## Troy-facing definition of done

Done when Troy can open one place and answer:

1. What valuable ideas did we miss?
2. What hidden assets exist?
3. What products can be assembled from existing assets?
4. What markets, customers, and revenue paths are implied?
5. What is active, incubating, parked, or dead?
6. What should be done next without asking Troy?
7. What is broken, degraded, newly released, up and coming, promotion-ready, or blocked?
8. What evidence proves it?
