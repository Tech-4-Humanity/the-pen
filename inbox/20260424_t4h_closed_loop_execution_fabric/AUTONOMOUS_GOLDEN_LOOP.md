# Autonomous Golden Loop — T4H Operating Doctrine

## Doctrine
The autonomous golden loop is the operating cycle that keeps the T4H execution fabric alive, useful, profitable, and self-correcting.

## Loop

```text
Sense -> Decide -> Act -> Prove -> Monetise -> Learn -> Scale -> Repeat
```

## Meaning

### 1. Sense
Detect opportunities, failures, stale workflows, broken automations, customer signals, and revenue leaks.

### 2. Decide
Select the next best action using health state, value state, cost state, portfolio priority, and proof gaps.

### 3. Act
Trigger the correct workflow, Lambda, agent, campaign, document generator, client delivery path, or repair routine.

### 4. Prove
Write evidence to logs, receipts, Drive docs, GitHub commits, registry rows, workflow runs, and Command Centre widgets.

### 5. Monetise
Bind each useful execution to a product, offer, billing event, Stripe object, invoice, report, lead magnet, or service package.

### 6. Learn
Compare outcome against expected value, cost, latency, failure rate, conversion, and customer signal.

### 7. Scale
Increase frequency, parallelism, distribution, portfolio replication, or sales pressure where proof and ROI justify it.

### 8. Repeat
Run continuously without waiting for human review unless an action is destructive, irreversible, or production-billing sensitive.

## Non-Negotiables

- No silent failure.
- No execution without proof.
- No proof without a link.
- No link without registry.
- No value without attribution.
- No attribution without owner.
- No product without distribution.
- No distribution without feedback.
- No loop without a receipt.

## Operating State
Every system, offer, workflow, and business must be classified as one of:

- READY
- FIRING
- DEGRADED
- REPAIRING
- BLOCKED
- RETIRED

## Reality Classification

- PARTIAL / UNPROVEN: built but not executed.
- PROMOTED-BUT-UNPROVEN: productised but no revenue proof.
- OPERATING: firing with health proof.
- REAL: execution + revenue + recovery + repeatability proven.

## Command Centre Required Views

- Golden Loop board
- Scheduler health
- Execution economy
- Revenue assets
- Offer pipeline
- Portfolio rollout
- Receipt index

## Close Rule
The loop is not closed because a document says it is closed. It is closed only when the receipt proves execution, recovery, value, and repeatability.
