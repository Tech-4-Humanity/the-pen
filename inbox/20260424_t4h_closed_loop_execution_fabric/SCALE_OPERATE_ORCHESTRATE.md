# 3. ORCHESTRATE LOOP

## Orchestration Roles

### Control Tower
Owns execution truth, health, proof, and receipts.

### Revenue Router
Owns offer mapping, billing events, Stripe routing, and revenue proof.

Owns client onboarding, service checklist, delivery artefacts, and proof packs.

### Optimizer

# 7. RECEIPT AND EVIDENCE RULE

The system is not complete until a receipt exists with:

- GitHub commits
- Drive links
- Supabase rows
- Stripe objects or stubs
- workflow run IDs
- runtime proof
- Command Centre widget references
- Reality Ledger classification

Classification rules:

- PARTIAL / UNPROVEN: built but not executed
- PROMOTED-BUT-UNPROVEN: productised but no revenue proof
- OPERATING: firing with health proof
- REAL: execution + revenue + recovery + repeatability proven
