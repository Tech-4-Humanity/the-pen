# Portfolio Product Fit Map — Vertical AI Operating Systems

## Core Thesis

AI for Tradies is not a standalone isolated product. It is one vertical expression of a reusable AI Operating System family that can sit under existing Troy Latter / Tech 4 Humanity companies and brands.

The same engine can be renamed, packaged, and priced differently per market while preserving the same underlying capability blocks:

- Answer / Intake
- Analyse
- Write
- Book / Schedule
- Quote / Proposal
- Follow-up / Convert
- Deliver / Execute
- Evidence / Govern
- Track / Dashboard
- Optimise
- Retain
- Loop

## Master Product Pattern

Generic name: Vertical AI Operating System
Market-facing formula: AI for [Market] / [Market] Growth Desk / [Market] Evidence Desk / [Market] Operating System

Core backend: shared agent registry, product catalogue, pricing engine, evidence ledger, API layer, site scaffold, Stripe model, and Supabase schema.

## Strategic Structure

Do not create 30 disconnected products.

Create one reusable core platform:

Vertical AI OS Core
- agent registry
- agent runtime
- product catalogue
- pricing catalogue
- Stripe billing
- Supabase persistence
- evidence ledger
- site template
- API contract
- dashboard template
- telemetry and recovery

Then create vertical wrappers:

1. AI for Tradies
2. AI for Professionals
3. AI for Self-Employed
4. Outcome Ready Providers
5. Enter Australia Market Entry
6. Education AI OS
7. Health AI OS
8. WorkFamilyAI Role Desk
9. AHC Coaching Layer
10. AI Sweet Spots Diagnostic Layer

## Key Decision

Outcome Ready should not absorb everything. It should own outcome/evidence-heavy services.

EnterAustralia.tech should own overseas-to-Australia market entry.

AHC should own the coaching/transformation layer.

WorkFamilyAI should own human-role and workforce packaging.

AI Sweet Spots should own diagnostics and routing.

Tech 4 Humanity should provide the credibility/governance/trust umbrella.

The product engine underneath should remain reusable and mostly invisible.
