# Doolittles — Adoption Journey + Website Plan

## Purpose
Build Doolittles as a journey, not a giant-bang enterprise integration. Start with simple communication examples, then progressively show tools joining the conversation, agent pods preparing work, and eventually whole-organisation change propagation.

## Core positioning
Do not start by claiming SAP will rewire itself. Start by showing a message becoming useful immediately.

Then show Slack, Copilot, ServiceNow, Salesforce, LMS and other systems joining in.

The audience must see the maturity curve:
1. message;
2. personalised message;
3. tool-aware message;
4. generated docs/training;
5. ticket/workflow creation;
6. cross-tool activation;
7. full organisational movement.

---

## Product line
Start with a message. End with an organisation moving.

## Tone
Practical, not magical. Show small proofs before big claims.

## Journey stages for the website

### Stage 1 — Simple message translation
**Demo:** executive writes one announcement.

Doolittles creates:
- CEO summary;
- French email for Johnny;
- Slack bullet list for Mary;
- neuroinclusive checklist;
- manager talking points.

**Value:** people hear the same thing in the way they need.

**Page assets:**

- sample email;

## Website page structure

### Page 1 — Doolittles Home
Headline: Talk to the animals. Make the animals talk to each other.
Subheadline: One announcement becomes the right message, task, document, training and system action for every person and tool.
CTA: Try a command.

### Page 2 — Simple Translation Demo
Use newsletter/email/Slack examples. No heavy integrations. Build confidence.

### Page 3 — Day in the Life of a Tool
Show what happens to Slack, ServiceNow, LMS, Salesforce, SAP, Microsoft and a support desk before and after Doolittles.

### Page 4 — Before / After Case Studies
Case studies:
1. Microsoft rollout;
2. petrol price shock;
3. call centre improvement;
4. SAP change preparation;
5. marketing campaign sprint.

### Page 5 — Neuroinclusive Communication
Show preference profiles, ambiguity reduction, concrete checklists, channel matching and low-meeting options.

### Page 6 — Partner Integrations
Slack, Microsoft, ServiceNow, Salesforce, SAP, LMS, GitHub, HRIS, payroll, facilities/IoT.

### Page 7 — Readiness Board
Live-style panel showing who heard, what moved, what is blocked and what proof exists.

7. Artefacts generated.

## Example case study — Marketing campaign sprint

### Announcement
"We need a campaign for the new AI readiness offer by tomorrow."

### Before
- meeting to define audience;
- copywriter drafts;
- designer waits;
- sales asks for messaging;
- email team waits;
- social team waits;
- CRM segmentation happens late.

### After
- Doolittles identifies standard campaign pathway;
- removes unnecessary tools/steps;
- drafts landing page copy;
- drafts email;
- drafts LinkedIn post;
- creates sales one-pager;
- creates CRM segment stub;
- creates Slack launch pack;
- logs evidence.

### Tool reduction angle
Doolittles can remove three manual coordination jobs:
1. campaign brief rewrite;
2. internal status chasing;
3. audience-specific message reformatting.

## Minimum viable demo path
Do not start with SAP live integration.

Build in this order:
1. Static scenario pages.
2. Button-generated stakeholder messages.
3. Slack-style outputs.
4. ServiceNow-style ticket/KB stub.
5. LMS training module stub.
6. Salesforce customer-impact stub.
7. SAP readiness stub.
8. Readiness board.
9. Evidence log.

---

## Why this works commercially
The initial buyer does not need to believe in full autonomous enterprise change. They only need to see:
- a better newsletter;
- a better Slack message;
- a better support ticket;
- a better training module;
- a better readiness board.

Then the website graduates them into the larger vision.
