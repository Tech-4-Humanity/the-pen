# Chat Project Migration v1.0

## Purpose
Turn scattered ChatGPT threads into a small, durable project operating layer that reduces restart friction, preserves decisions, and routes work into execution, income, research, and archive surfaces.

## Native boundary
Direct bulk movement of existing ChatGPT chats into ChatGPT Projects is not available through this tool surface. This file defines the operating model, taxonomy, migration rules, evidence model, pinned-state templates, migration sprint, and classifier schema.

## Operating principle
Do not organise every historical chat. Build a control tower around active value.

## Project definitions

### 1. Command Centre / Spine
Purpose: Run the machine.
Includes: Bridge, Pen, MCP, receipts, self-healing, telemetry, orchestration, Lambda, EventBridge, runtime rules, Reality Ledger.
Default status: PARTIAL until runtime receipts and recovery proof exist.

### 2. Jobs / CV / Immediate Income
Purpose: Generate income now.
Includes: job applications, CVs, cover letters, LinkedIn Premium, outreach, recruiter messages, contract/day-rate opportunities.
Default status: ACTIVE.

### 3. GTM + Revenue Engine
Purpose: Turn capability into offers and campaigns.
Includes: AI Sweet Spots, AI for Tradies, WorkFamilyAI offers, product packaging, pricing, funnels, lead generation, partnership campaigns.
Default status: ACTIVE.

### 4. Tech4Humanity
Purpose: Parent ecosystem, mission, governance, public identity.
Includes: ecosystem architecture, ConsentX, MyNeuralSignal, ethics, public positioning, policy, partner story.
Default status: ACTIVE.

### 5. Outcome Ready + Reading Buddy
Purpose: Education, evidence, NDIS-adjacent offers, reading improvement products.
Includes: Reading Buddy, Thriving OS, curriculum validation, teacher evidence, signal-to-outcome chain.
Default status: ACTIVE.

### 6. WorkFamilyAI
Purpose: Workforce operating system.
Includes: 10x10x10, role maps, AI worker models, workforce agents, leadership language packs, role documents.
Default status: ACTIVE.

### 7. NeuroPAK + GC-BAT + BCI
Purpose: Neurotechnology, BCI governance, futures, standards, and ethical infrastructure.
Includes: GC-BAT vignettes, BCI committee work, NeuroPAK architecture, standards, futures scenarios.
Default status: CONTINUOUS.

### 8. Research Vault
Purpose: Intake layer for future signal.
Includes: papers, studies, imported documents, unfinished ideas, discoveries, source material.
Default status: INTAKE.

### 9. Archive / Parking Lot
Purpose: Keep low-value history out of the control layer.
Includes: duplicates, dead ideas, old rabbit holes, one-off experiments, stale threads.
Default status: ARCHIVED.

## Migration rule
Move a thread only if it is one or more of the following:
- active in the last 90 days
- revenue related
- recurring
- unfinished execution
- infrastructure dependent
- audit or governance relevant
- reusable as an asset
- linked to a product, offer, article, repo, receipt, or external obligation

Archive everything else.

## Project states
- REAL: moved or captured with evidence and next action
- PARTIAL: classified but not fully moved or evidenced
- BLOCKED: cannot be moved because native capability is unavailable
- ARCHIVED: deliberately parked
- DUPLICATE: merged into stronger thread or state page

## Evidence requirements
A migrated thread becomes REAL only when at least one evidence item exists:
- manually verified ChatGPT project move
- exported chat file hash
- GitHub issue, commit, or PR
- linked artifact path
- receipt ID
- project pinned state update
- external file reference

## Classifier schema
thread_title,source_id,source_url,project,status,confidence,value_score,revenue_relevance,execution_relevance,audit_relevance,active_since,next_action,assets_found,duplicate_of,evidence,gaps

## Manual migration sprint
1. Create the nine ChatGPT Projects if absent.
2. Add the pinned note template to each project.
3. Move Jobs / CV / Immediate Income first.
4. Move Command Centre / Spine second.
5. Move GTM + Revenue Engine third.
6. Move Outcome Ready + Reading Buddy fourth.
7. Archive duplicate and low-value history.
8. Export or copy high-value threads that cannot be moved.
9. Record moved threads against the classifier schema.
10. Bind completed project states to the Reality Ledger.

## Operating guardrails
- Do not move everything.
- Do not create hundreds of projects.
- Do not let archive become another active project.
- Do not treat project creation as completion.
- Do not classify a migration as REAL without evidence.
- Do not spend human time on low-value historical sorting.
