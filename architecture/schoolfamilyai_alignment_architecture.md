## Purpose

SchoolFamilyAI is the child, school, family and support-system predecessor to WorkFamilyAI. It is not WorkFamilyAI made smaller. It converts the archaic job-description model into a developmental, capability, signal and outcome graph.

WorkFamilyAI models how adult teams, roles, jobs, responsibilities, agents and families interlock.

SchoolFamilyAI models how learners, families, teachers, schools, peers and support systems interlock before fixed work identity hardens.

The operating principle is:

```text
role descriptions are temporary
capabilities are durable
signals are observable
outcomes are governable
```

## Alignment to WorkFamilyAI 9x9x9

WorkFamilyAI 9x9x9 remains useful as a coordination grammar, but it must be lifted away from fixed industrial roles.

| WorkFamilyAI object | SchoolFamilyAI equivalent | Forward-compatible lift |
| --- | --- | --- |
| Team | Learning circle | Temporary support constellation |
| Role | Capability function | Dynamic contribution pattern |

| Responsibility | Support obligation | Duty of care plus outcome path |

| Handover | Continuity record | Evidence and support memory across transitions |

## Core transition

Old model:

```text
child -> grade -> subject -> report -> job pathway
```

Target model:

```text
need -> signal -> identity -> consent -> capability -> support route -> intervention -> evidence -> outcome -> learning continuity
```

## Governance non-negotiables

SchoolFamilyAI cannot be sold as child surveillance.

It must be sold as:

```text
human support amplification with consent, evidence and recovery
```

Required controls:

- guardian consent
- school authority mapping
- child-safe explanations
- no diagnosis claims
- no unsupported risk scoring
- no secret profiling
- opt-out / revocation
- evidence provenance
- human review for consequential decisions
- recovery path for wrong recommendations
- telemetry ledger for state changes
