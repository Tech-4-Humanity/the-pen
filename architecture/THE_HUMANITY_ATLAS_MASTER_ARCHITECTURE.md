# The Humanity Atlas Master Architecture

Status: PARTIAL
Owner: Troy Latter
Canonical spine: `architecture/AI_FOR_HUMANITY_3_1_INTEGRITY_STACK_SPINE.yaml`

## Purpose

The Humanity Atlas is the navigation surface for the Tech4Humanity / AI for Humanity 3.1 portfolio. It is not a new product silo. It is the atlas view over the seven-layer Integrity Stack.

Its job is to show how human needs, signals, identities, consent states, intents, interventions, evidence, outcomes, products, research themes, economics and governance connect in one reusable system.

## Core transition

Old state:

```text
research themes -> product sketches -> diagrams -> scattered opportunities
```

Target state:

```text
need -> signal -> identity -> consent -> intent -> route -> act -> measure -> learn -> govern -> recover
```

## Non-negotiable model

Every product, research card, visual, workflow, agent and business activity must resolve to at least one of these objects:

1. Need
2. Signal
3. Identity
4. Consent
5. Intent
6. Route
7. Intervention
8. Evidence
9. Outcome
10. Learning
11. Governance
12. Recovery
13. Economic path

If an asset cannot resolve to the model, it is either parking-lot material or a gap.

## Product reuse principle

Products are assemblies, not isolated builds.

A product should declare:

- need served
- intended users
- reusable engines used
- stack layers touched
- required evidence
- governance boundary
- telemetry requirement
- commercial path
- recovery path

## Missing runtime pieces

The Atlas remains PARTIAL until these are executed and evidenced:

1. SQL runtime schema deployed or at least validated.
2. Canonical change row written to the ledger.
3. Evidence contract defined and enforced.
4. Product assembly matrix linked to products.
5. Telemetry continuity present across loop stages.

## Acceptance criteria for REAL

A Humanity Atlas artefact or product claim is REAL only when it has:

- a declared need;
- a declared intent;
- actor, identity and consent binding;
- stack layer mapping;
- evidence records;
- measurable outcome;
- economic path or proof;
- recovery path;
- ledger entry;
- telemetry continuity.

Without those, it remains PARTIAL.
